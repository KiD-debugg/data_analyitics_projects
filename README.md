# Data Analytics Projects

This repository is an index for my data analytics projects. On my computer, the
project repositories are organized as sibling folders alongside this README.
Each project is maintained separately with its own code, data, analysis files,
and README.

## Projects

| Project | Description | Main contents |
|---|---|---|
| [bookings_project](https://github.com/KiD-debugg/bookings_project) | Analyzes multi-year travel bookings, including growth, revenue, package performance, and data quality. | `data/`, `notebooks/`, `src/`, `outputs/` |
| [jumia_black_friday](https://github.com/KiD-debugg/jumia_black_friday) | Explores Jumia product listings, prices, discounts, ratings, sellers, and promotional placement. | `data/`, `notebooks/` |
| [pesa_pulse_co](https://github.com/KiD-debugg/pesa_pulse_tech_co) | Profiles sample customer records from the JSONPlaceholder API and exports summary tables and a chart. | `analysis.py`, `output/` |
| pharmacy_project (https://github.com/KiD-debugg/pharmacy_project) | Cleans and explores pharmacy sales data, with a focus on transactions, data quality, and sales patterns. | `data/`, `notebooks/`, `src/` |
| safari_connect_analytics (not published) | Analyzes intercity transport operations using SQL, including routes, revenue, bookings, and driver performance. | `sql/`, `insights/`, `dashboard/` |
| [tech_hub_kenya_co](https://github.com/KiD-debugg/tech_hub_kenya_co) | Analyzes September electronics sales, product revenue, and high-value transactions. | `sales_analysis.ipynb`, `data/`, `output/` |

Each project repository has its own `README.md` with project-specific details
and instructions. Projects marked **not published** are currently available
only in my local project folder.

## Organization

- Each project is version-controlled in its own repository.
- Project-specific notebooks, scripts, SQL, data, and outputs stay in that
  project's repository.
- Make Git changes from inside the relevant project folder.
- Add future analytics projects as new sibling folders and give each one its
  own README.
